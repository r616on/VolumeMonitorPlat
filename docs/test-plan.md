# План испытаний и валидации: Volume Adapter

Документ определяет процедуры испытаний для верификации системных требований к изделию Volume Adapter v1.0.1.

**Ревизия:** A  
**Автор:** Test & Validation Engineer  
**Дата:** 2026-07-23  
**Ссылки:** `system-requirements.md`, `hardware.md`, `protocol.md`, `architecture.md`

---

## 1. Стратегия испытаний

### 1.1. Уровни испытаний

| Уровень | Название | Объём | Где выполняется | Когда |
|---|---|---|---|---|
| **L1** | Функциональные (стендовые) | Все функциональные и интерфейсные требования | Рабочее место разработчика | После каждой сборки |
| **L2** | Электрические и интерфейсные | Все SYS-ELEC-*, SYS-IF-* | Лабораторный стенд | Перед релизом v1.1 |
| **L3** | Климатические и механические | Все SYS-ENV-* | Климатическая камера, вибростенд | Перед пилотной партией |
| **L4** | EMC | Все SYS-EMC-* | Аккредитованная EMC-лаборатория | Перед сертификацией |
| **L5** | Надёжность (ускоренные) | SYS-REL-* | Стенд ускоренных испытаний | Перед серийным производством |

### 1.2. Критерии качества (Performance Criteria)

По ISO 16750-1:

| Класс | Описание | Применение |
|---|---|---|
| **A** | Все функции в пределах спецификации во время и после воздействия | Функциональные тесты, BCI, ESD (контактный) |
| **B** | Допустимо временное отклонение, самовосстановление после воздействия | Вибрация, термоциклирование |
| **C** | Допустим сброс/перезагрузка с автоматическим восстановлением | ESD (воздушный), провалы питания |
| **D** | Допустимо необратимое отклонение функции, но без угрозы безопасности | Не применяется (non-safety устройство) |

### 1.3. Образцы для испытаний

| # | Назначение | Количество |
|---|---|---|
| S1 | Функциональные тесты (L1–L2) | 2 шт. |

## 2. Группа A: Функциональные испытания (L1)

### TC-A01. Протокол — формат сообщений

| Поле | Значение |
|---|---|
| **ID** | TC-A01 |
| **Требование** | SYS-FUNC-001 |
| **Класс качества** | A |

**Описание:** проверка формата `[JSON]\n` на приём и передачу.

**Оборудование:** хост-PC, `test_runner.py`.

**Процедура:**
1. Отправить корректное `[{"command":"ping"}]\n`.
2. Отправить сообщение без `[ ]` — `{"command":"ping"}\n`.
3. Отправить сообщение без `\n`.
4. Отправить пустую строку `\n`.
5. Отправить `not json\n` внутри `[...]`.

**Критерии:**
- Шаг 1: ответ `[{"status":"success",...}]\n`.
- Шаг 2: ответ `[{"status":"error","message":"Message must be enclosed in [ ]"}]\n`.
- Шаг 3: нет ответа (ждёт `\n`).
- Шаг 4: нет ответа (trim удаляет пустую строку).
- Шаг 5: ответ `[{"status":"error","message":"Invalid JSON",...}]\n`.

### TC-A02. Протокол — welcome-сообщение

| Поле | Значение |
|---|---|
| **ID** | TC-A02 |
| **Требование** | SYS-FUNC-002 |
| **Класс качества** | A |

**Процедура:**
1. Подать питание 5V. Захватить TX-линию логическим анализатором.
2. Измерить задержку от фронта питания до первого байта welcome-сообщения.

**Критерии:**
- Задержка ≤ 500 мс.
- Поля: `status="ready"`, `device` (непустое), `protocol="JUDI"`, `version="1.0.1"`, `volume_range`, `bass_range`, `mode`.

### TC-A03. Протокол — время ответа

| Поле | Значение |
|---|---|
| **ID** | TC-A03 |
| **Требование** | SYS-FUNC-003 |
| **Класс качества** | A |

**Процедура:**
1. Отправить `ping` (без I2C), осциллографом измерить интервал: конец `\n` запроса → начало `[` ответа.
2. Отправить `set_volume` со значением 128. Измерить интервал.
3. Повторить 100 раз, записать максимальное значение.

**Критерии:**
- `ping`: ≤ 20 мс.
- `set_volume`: ≤ 50 мс.
- 100% ответов в пределах допуска.

### TC-A04. Управление потенциометрами — передаточная характеристика Volume

| Поле | Значение |
|---|---|
| **ID** | TC-A04 |
| **Требование** | SYS-FUNC-010 |
| **Класс качества** | A |

**Оборудование:** мультиметр, хост-PC.

**Процедура:**
1. Измерить сопротивление между CN1-2 и GND_Isolated при value = 0.
2. Последовательно отправлять `set_volume` с шагом 32: 0, 32, 64, …, 224, 255. На каждом шаге измерять R.
3. Построить график R(value) = value / 255 × 5 кОм.

**Критерии:** R ∈ [R_expected × 0.8, R_expected × 1.2] для каждого значения.

### TC-A05. Управление потенциометрами — сохранение NV (volume memo)

| Поле | Значение |
|---|---|
| **ID** | TC-A05 |
| **Требование** | SYS-FUNC-011 |
| **Класс качества** | A |

**Процедура:**
1. `set_volume_memo` со значением 200.
2. `ping` → `volume=200`.
3. Отключить питание на 30 с.
4. Подать питание, `ping` → `volume=200`.
5. Повторить для граничных значений 0 и 255.

**Критерии:** после power-cycle `volume` = записанному (±1 шаг для значения 0, т.к. минимальное сопротивление потенциометра ≈ 30–100 Ω).

### TC-A08. Эмуляция кнопок — базовое нажатие/отпускание

### TC-A09. Эмуляция кнопок — взаимная блокировка

| **Класс качества** | A |

## 3. Группа B: Электрические испытания (L2)

### TC-B01. Диапазон напряжения питания

| Поле | Значение |
|---|---|
| **ID** | TC-B01 |
| **Требование** | SYS-ELEC-001 |
| **Класс качества** | A |

**Оборудование:** лабораторный БП с регулировкой 4.0V–6.0V, шаг 0.1V.

**Процедура:**
1. Установить 5.0V. Выполнить `ping`, `set_volume(128)`, `set_bass_level(64)` — baseline.
2. Снижать напряжение до 4.5V с шагом 0.1V, на каждом шаге выполнить `ping` × 10.
3. Повышать до 5.5V, на каждом шаге `ping` × 10.
4. Провести измерения на границах 4.4V и 5.6V — вне диапазона.

**Критерии:**
- 4.5V–5.5V: 100% успешных `ping`-ответов, отсутствие I2C NACK.
- 4.4V и 5.6V: допустимы сбои (за пределами спецификации USB).

## 7. Группа F: Испытания на надёжность (L5)

### TC-F01. EEPROM — циклическая запись (ModeManager)

| Поле | Значение |
|---|---|

| **Требование** | SYS-REL-002 |
| **Класс качества** | A (до 80 000 циклов) |
