# Системные требования: Volume Adapter

Аппаратный I2C/USART-мост управления автомобильным аудиопроцессором на базе Arduino Nano (ATmega328P). Документ определяет системные требования с прослеживаемостью до методов верификации и применимых стандартов.

**Ревизия:** A  
**Автор:** Systems Engineer (Automotive Electronics)  
**Дата:** 2026-07-23  
**Применимые стандарты:** CISPR 25, ISO 11452-4, ISO 16750-3/4, IEC 60068-2

> **Питание:** изделие получает питание по USB (+5V) от головного устройства (ГУ). ГУ обеспечивает стабилизированное, фильтрованное питание, соответствующее автомобильным стандартам. Стандарты ISO 16750-2 (электрические нагрузки бортсети 12V) и ISO 7637-2 (переходные импульсы) относятся к входному питанию ГУ и **неприменимы** непосредственно к изделию.

---

## 1. Назначение и область действия

Настоящий документ определяет системные требования к устройству Volume Adapter (далее — «изделие»), предназначенному для установки в салоне транспортного средства категории M1 (легковые автомобили). Питание — USB +5V от головного устройства. Изделие не является элементом безопасности (non-safety-critical) и классифицируется как устройство класса информационно-развлекательных систем (Infotainment Accessory).

## 3. Электрические требования

Изделие питается по USB (+5V) от головного устройства. Питание уже стабилизировано и отфильтровано ГУ. Собственная защита по входу питания не требуется.

### 3.1. Номинальное питание

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-ELEC-001** | Изделие должно функционировать при напряжении питания USB 5V ±10% (4.5V–5.5V), согласно спецификации USB 2.0. | Все функции в пределах спецификации (приём команд, ответы по UART, I2C-обмен без NACK). | Испытание при U<sub>min</sub> = 4.5V, U<sub>nom</sub> = 5.0V, U<sub>max</sub> = 5.5V; мониторинг `ping`-ответа. |
| **SYS-ELEC-002** | Потребляемый ток в установившемся режиме ≤ 200 мА при 5.0V (предел USB 2.0 для low-power device: 1 unit load = 100 мА, high-power: 500 мА — запас 2.5×). | I ≤ 200 мА. | Измерение амперметром в последовательной цепи питания USB. |
| **SYS-ELEC-003** | Потребляемый ток в режиме сна / REM off ≤ 30 мА при 5.0V. | I ≤ 30 мА. | Программное отключение всех потребителей, измерение тока. |

## 4. Требования к интерфейсам

### 4.1. UART (Serial)

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-IF-001** | Параметры UART: 115200 бод, 8 бит данных, 1 стоп-бит, без контроля чётности (8N1). | Приём/передача без ошибок кадрирования на протяжении 10 000 сообщений. | Тестовый прогон 10 000 JSON-команд + проверка CRC-счётчиком. |
| **SYS-IF-002** | Уровни сигналов UART: 5V TTL (Arduino Nano встроенный USB-UART). | V<sub>OH</sub> ≥ 4.2V, V<sub>OL</sub> ≤ 0.8V при I<sub>load</sub> ≤ 1 мА. | Осциллографирование TX/RX под нагрузкой. |
| **SYS-IF-003** | Максимальная длина буфера сообщения: 256 байт (`StaticJsonDocument<256>`). Сообщения длиннее 256 байт должны игнорироваться с ошибкой. | При превышении — ответ `{"status":"error","message":"Message too long"}`. | Инжекция сообщений длиной 256, 257, 300 байт. |

### 4.2. I2C (изолированная шина)

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-IF-010** | Частота I2C: 100 кГц (Standard-mode). | ±1% по осциллографу. | Осциллографирование SDA/SCL, измерение периода SCL. |
| **SYS-IF-011** | Напряжение изолированной стороны I2C: 3.3V ±10%. Подтяжки R202, R212 = 4.7 кОм к +3.3V_Isolated. | Уровни V<sub>IH</sub> ≥ 2.31V, V<sub>IL</sub> ≤ 0.99V (MCP4561, 0.7/0.3 × V<sub>DD</sub>). | Измерение мультиметром/осциллографом. |
| **SYS-IF-012** | Гальваническая развязка между ардуиновской (5V) и изолированной (3.3V) сторонами I2C: напряжение изоляции ≥ 560V<sub>peak</sub> (ISO1540DR, спецификация). | Отсутствие пробоя при испытательном напряжении 500V DC в течение 60 с. | Мегомметр, тест изоляции «pin-to-pin» (SDA1 → SDA2). |
| **SYS-IF-013** | Error handling: при NACK от любого устройства на изолированной шине функция `Wire.endTransmission()` возвращает код ошибки ≠ 0, протокол возвращает JSON-ошибку `"I2C communication failed (…)"`. | Моделирование NACK: отключение одного MCP4561 от шины. | Программный тест: `set_volume`, `set_bass_level` при отключённом устройстве. |

### 4.3. GPIO-выходы эмуляции кнопок (ButtonController)

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|

| **SYS-IF-021** | Одновременно может быть активна только одна кнопка (взаимная блокировка в ButtonController). | При `press(N)` и последующем `press(M)` — пин N переходит в LOW, пин M — в HIGH. | Осциллографирование двух пинов одновременно. |
| **SYS-IF-022** | Выходной ток каждого GPIO ≤ 20 мА (ограничение ATmega328P, абсолютный максимум 40 мА на вывод). | Измерение тока на каждом выходе в состоянии HIGH. | Последовательный амперметр между пином и резистором 220 Ω. |

### 4.4. Вход пресет-детектора (PresetDetector)

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-IF-030** | Пин A3 в режиме `INPUT_PULLUP`. Переход из HIGH в LOW при замыкании фототранзистора оптопары U2. | V<sub>IL</sub> ≤ 1.5V (при засвеченной оптопаре), V<sub>IH</sub> ≥ 3.0V (при незасвеченной). | Измерение на A3 относительно GND_A. Подача управляющего тока через R114 (470 Ω) на светодиод U2. |
| **SYS-IF-031** | Прямой ток светодиода оптопары U2 (FOD817BW): 5–10 мА. Задаётся R114 = 470 Ω при управляющем напряжении 5V. | I<sub>F</sub> = (5V − V<sub>F</sub>) / 470 Ω ≈ 8 мА (V<sub>F</sub> ≈ 1.2V). | Измерение падения на R114, расчёт тока. |
| **SYS-IF-032** | Минимальная длительность импульса для детекции: 100 мкс (конфигурируемый параметр `_minPulseDur`). | Импульсы < 100 мкс игнорируются. Импульсы 100–200 мкс регистрируются. | Генератор импульсов (функциональный генератор) через оптопару. Измерение счётчика серии. |
| **SYS-IF-033** | Таймаут серии: 400 мс после последнего валидного импульса. | Серия завершается через 400 мс ±10%. | Программный тест: подача серии из N импульсов с интервалом 200 мс, контроль завершения. |

| **SYS-IF-041** | Защитный диод D1 (1N4148WQ-7-F) параллельно выходу CN2 для подавления обратного напряжения при коммутации индуктивной нагрузки. | Отсутствие выбросов > 5V на CN2 при коммутации реле 12V / 200 мА. | Осциллографирование CN2 с индуктивной нагрузкой (реле 12V). |

## 5. Функциональные требования

### 5.1. Протокол JUDI

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-FUNC-001** | Все сообщения протокола имеют формат `[JSON]\n`. | Приём и передача соответствуют формату. | Анализатор протокола, монитор порта. |
| **SYS-FUNC-002** | Welcome-сообщение передаётся при каждом включении питания (RESET) в течение ≤ 500 мс после подачи питания. | Задержка ≤ 500 мс. Содержит поля: `status`, `device`, `protocol`, `mode`, `volume_range`, `bass_range`, `version`. | Осциллографирование TX-линии, захват welcome-сообщения логическим анализатором. |
| **SYS-FUNC-003** | Ответ на любую команду передаётся в течение ≤ 20 мс с момента приёма завершающего `\n` (для команд без I2C) и ≤ 50 мс для команд с I2C (учёт таймаута `Wire.endTransmission`). | Задержка в пределах допуска. | Осциллографирование TX/RX, измерение интервалов. |

### 5.2. Управление потенциометрами

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-FUNC-010** | `set_volume` — запись значения 0–255 в регистр RAM Volume-потенциометра (MCP4561, адрес 0x2F, команда WRITE_WIPER0 = 0x00). Значение не сохраняется при выключении питания. | Измерение сопротивления движка Volume (CN1-2 через J4) относительно GND_Isolated. Соответствие: R = value / 255 × 5 кОм ±20%. | Мультиметр, подача команд с шагом 32 (0, 32, 64, …, 224). Построение передаточной характеристики. |
| **SYS-FUNC-011** | `set_volume_memo` — запись в RAM + NV (команда WRITE_NV_WIPER0 = 0x20). После цикла питания значение восстанавливается. | Отключение питания на 30 с → включение → `ping` → `volume` равно записанному. | Циклы питания, мониторинг `ping`. |
| **SYS-FUNC-012** | `set_bass_level` — запись в RAM + NV Bass-потенциометра (MCP4561, адрес 0x2E). | Аналогично SYS-FUNC-011 для Bass (CN1-3). | Мультиметр на CN1-3, подача команд. |
| **SYS-FUNC-013** | Диапазон допустимых значений для всех потенциометров: 0–255. Значения вне диапазона возвращают ошибку `"value must be 0-255"`. | Ответ при value = −1, 256, 999. | Программный тест (инжекция граничных значений). |

### 5.3. Эмуляция кнопок

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-FUNC-020** | `button_down(N)` — установка пина кнопки N в HIGH. Диапазон N: 1–7. | Осциллографирование пина. | Программный тест: поочерёдное нажатие кнопок 1–7. |
| **SYS-FUNC-021** | `button_up(N)` — установка пина кнопки N в LOW. | Осциллографирование пина. | Программный тест. |
| **SYS-FUNC-022** | При переходе между кнопками (press одной при зажатой другой) сначала отпускается первая, затем зажимается вторая. Задержка переключения ≤ 100 мкс. | Осциллографирование двух пинов: <100 мкс одновременного HIGH. | Двухканальный осциллограф. |
| **SYS-FUNC-023** | `change_preset` — импульс HIGH на D9 длительностью 500 мс ±5% (BUTTON_PRESS_DURATION_MS). | Измерение длительности импульса осциллографом. | Осциллограф на D9, команда `change_preset`. |

### 5.4. Детекция пресетов

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-FUNC-030** | PresetDetector должен регистрировать серии импульсов длиной 1–10 и возвращать подтверждённый номер через `getConfirmedPreset()`. | Две одинаковые серии подряд подтверждают пресет. ### 5.5. Управление REM и режимами

| ID | Требование | Критерий | Метод верификации |
|---|---|---|---|
| **SYS-FUNC-040** | `set_is_enable_rem` — управление пином A2. TRUE → HIGH, FALSE → LOW. Состояние сохраняется до следующей команды или RESET (сброс в LOW). | Соответствие осциллограммы A2 команде. | Осциллограф на A2. |
| **SYS-FUNC-041** | `set_mode` — запись режима (`standard` / `start_min_value`) в EEPROM. После перезапуска режим сохраняется. | Цикл питания → `get_mode` возвращает установленный режим. | Программный тест с циклами питания. |
| **SYS-FUNC-042** | В режиме `start_min_value` после RESET громкость устанавливается в 1 (команда `setVolume(1)`). | `ping` после старта возвращает `volume=1` (или близкое значение в пределах погрешности). | Цикл питания, мониторинг welcome + ping. |
| **SYS-FUNC-043** | `ping` возвращает полный статус: `volume`, `bass`, `preset`, `is_enable_rem`, `mode`. | Корректность всех полей в ответе. | Программный тест с известным состоянием. |

## 6. Требования к электромагнитной совместимости (EMC)

## 13. Пин D9: управление сменой пресета через оптопару U33 (CN1-4)

### 13.1. Назначение

Пин D9 (U77-12) реализует специализированный выход **смены пресета** — единственную в системе линию, использующую гальванически развязанную передачу цифрового логического сигнала на внешнее устройство через оптопару U33. Конфликта назначений нет: обе функции (импульс смены пресета и управление оптопарой U33) являются двумя сторонами **одной и той же цепи**.

### 13.2. Схема прохождения сигнала

```
Arduino D9 (U77-12) ──► R88 (470Ω, токоограничение LED) ──► U33 LED (анод)
U33 LED (катод) ──► GND_A
U33-4 (коллектор фототранзистора) ──► шина ACC_3.3V_K (+3.3V_Isolated)
U33-3 (эмиттер фототранзистора) ──► CN1-4 (цифровой логический вход внешнего устройства)
```

### 13.3. Электрический принцип

Оптопара U33 (FOD817BW) работает как **гальванически развязанный транзисторный ключ** с открытым коллектором:

| Состояние D9 | U33 LED | Фототранзистор | CN1-4 |
|---|---|---|---|
| LOW | Погашен | Закрыт (высокий импеданс) | Высокоимпедансное состояние (внешняя подтяжка внешнего устройства определяет уровень) |
| HIGH | I<sub>F</sub> ≈ 8 мА | Открыт (низкий импеданс, V<sub>CE(sat)</sub> ≤ 0.3V) | Подтянут к +3.3V_Isolated через открытый транзистор U33 |

Внешнее устройство имеет на входе CN1-4 цифровой вход с высоким импедансом (КМОП/ТТЛ-совместимый). Ток через CN1-4 определяется только входным током утечки приёмника (единицы микроампер) — **утечки и паразитного потребления нет**. Напряжение логической единицы: +3.3V (уровень шины ACC_3.3V_K за вычетом V<sub>CE(sat)</sub>).

### 13.4. Протокол: команда `change_preset`

```
→ [{"command":"change_preset"}]
← [{"status":"success","command":"change_preset","message":"Button press simulated (500ms)"}]

Электрически:
  D9: LOW ──► HIGH (500 мс) ──► LOW
  CN1-4: высокий импеданс ──► +3.3V (500 мс) ──► высокий импеданс
```

Импульс +3.3V длительностью 500 мс на цифровом входе CN1-4 интерпретируется внешним устройством как команда смены пресета аудиосистемы.

### 13.5. Ключевые параметры

| Параметр | Значение | Примечание |
|---|---|---|
| Прямой ток LED U33 | 8.1 мА | (5V − 1.2V) / 470Ω |
| Напряжение на CN1-4 (HIGH) | +3.3V (минус V<sub>CE(sat)</sub> ≤ 0.3V) | Уровень логической единицы |
| Выходной ток CN1-4 (HIGH) | ≤ 10 мкА | Входной ток утечки приёмника (типовой КМОП-вход) |
| Длительность импульса | 500 мс ±5% | `BUTTON_PRESS_DURATION_MS` |
| Гальваническая развязка | ≥ 5000 V<sub>RMS</sub> | Спецификация FOD817BW |
| Задержка включения/выключения | ≤ 18 мкс | t<sub>on</sub>/t<sub>off</sub> FOD817BW |

### 13.6. Отличие от эмуляции кнопок (ButtonController)

| Характеристика | D9 + U33 → CN1-4 | ButtonController (D3–D8, D10 → H1) |
|---|---|---|
| Тип выхода | Цифровой логический сигнал, гальванически развязанный | Прямой GPIO, без развязки |
| Физический уровень | +3.3V (изолированная сторона) | +5V (сторона Arduino) |
| Разъём | CN1-4 | H1 |
| Протокольная команда | `change_preset` (импульс 500 мс) | `button_down`/`button_up` (статический уровень) |
| Назначение | Сигнал смены пресета аудиопроцессора | Универсальная эмуляция кнопок магнитолы |

### 13.7. Преимущества схемы

1. **Гальваническая развязка:** цифровой вход внешнего устройства полностью изолирован от Arduino — отсутствуют контуры заземления и синфазные помехи.
2. **Согласование уровней:** внешнее устройство получает сигнал уровня +3.3V независимо от напряжения питания Arduino (5V).
3. **Защита от перенапряжения:** оптопара выдерживает до 70V между коллектором и эмиттером (V<sub>CEO</sub> FOD817BW), что исключает повреждение внешнего устройства при отказе Arduino.
4. **Отсутствие сквозных токов:** высокоимпедансный вход приёмника на CN1-4 гарантирует, что ток через фототранзистор определяется только током утечки входа (единицы мкА) — паразитного потребления нет.
